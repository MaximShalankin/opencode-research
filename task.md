# Задача: воспроизведение научной статьи (масштабированная постановка)

Ты — исследовательский агент. Пройди полный путь: изучи статью, извлеки
воспроизводимый рецепт, реализуй модель, обучи её на масштабированных
данных, получи baseline-метрику и напиши отчёт с доказательствами.
Работай в `workspace/`.

## Память и источники

- Статья проиндексирована в памяти vault-core (MCP, коллекция `papers`,
  документ `aiayn`). Используй инструменты `vault_search` (запрос,
  `source="papers"`, `top_k`, `mode="snippets"|"full"`) и `vault_get_note`
  (по id/rel-пути). В выдаче есть страница (`p. N`) — цитируй её.
- Данные: `data/multi30k/` (train/val/test, en→de). Сеть запрещена,
  используй только эти файлы.
- Статья и данные — только чтение; не изменяй их.

## Что сдать (все файлы — в `workspace/`)

    "model":          {"layers": {"value": 0, "page": 0},
                       "d_model": {"value": 0, "page": 0},
                       "heads": {"value": 0, "page": 0},

    "optimizer":      {"name": {"value": "...", "page": 0},
                       "betas": {"value": [0.0, 0.0], "page": 0},
                       "eps": {"value": 0.0, "page": 0},
                       "warmup_steps": {"value": 0, "page": 0},
                       "schedule": {"value": "...", "page": 0}},
    "batch_tokens":   {"value": 0, "page": 0},
    "eval":           {"metric": {"value": "...", "page": 0},
                       "test_set": {"value": "...", "page": 0}},

Каждое поле `paper` — `{value, page}`; `page` — страница статьи из выдачи
MCP. Значения не выдумывай: если поля в статье нет — `{"value":
"не задано", "page": null}`. `implementation` — твой масштабированный
конфиг (2–4 слоя, d_model 256–512, 4–8 голов, FFN 1024–2048).

2. **`PLAN.md`** — стадии, бюджеты, риски, критерии успеха.

3. **Код** — `*.py` (PyTorch): подготовка данных, BPE/токенизация,
   модель, обучение, оценка. Запускается из `workspace/` одной командой,
   описанной в README или в начале скрипта.

4. **`logs/train.log`** — лог обучения (эпохи, loss, val BLEU, время).

5. **`metrics.json`**:

```json
{

  "config": {"layers": 2, "d_model": 256, "heads": 4, "d_ff": 1024,

```

`test_bleu` — sacreBLEU (`13a`) на `test_2016_flickr` (en→de), посчитанный
из предсказаний модели. Числа — только из реального запуска.

6. **`REPORT.md`** — таблица «утверждение → значение → доказательство»
   (файл/лог/страница статьи). Обязательно разделы: «воспроизведено»,
   «не воспроизведено», «не проверялось». Для фактов из статьи указывай
   страницу (`p. N`).

## Ограничения

- Масштаб: Multi30k, малый Transformer, бюджет ≤ 2 часов на обучение.
- Выбирай лучшую эпоху по val BLEU и считай финальный `test_bleu` с
  лучшего чекпоинта: на малом Multi30k модель переобучается после
  нескольких эпох.
- Не заявляй полное воспроизведение WMT14/28.4 BLEU: это другая постановка.
  Явно отделяй «наш baseline» от чисел статьи.
- Не хардкодь метрику и не копируй числа из статьи в `metrics.json`.
- Сеть: запрещена. Данные и пакеты — локально.
- Сид 42; фиксируй конфиг и версии.

## Критерии приёмки

- `recipe.json` заполнен по статье, у ключевых полей есть страницы.
- Код обучается и считает BLEU; `metrics.json` и `logs/train.log`
  согласованы, `test_bleu` посчитан из исполнения.
- `REPORT.md` без необоснованных чисел; цитаты страниц совпадают с
  первоисточником.
- В логе MCP видны вызовы `vault_search`/`vault_get_note` (статья
  использовалась через память, а не только чтением файла).
